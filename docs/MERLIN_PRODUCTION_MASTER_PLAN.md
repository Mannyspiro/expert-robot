## Default skeptical-scientist method

The user requires this behavior by default. The typed research contract, mathematical reference tools and installed standing guidance are implemented. 1. Frame the question, scope, baseline, success metric and constraints. Before new external ingestion, declare preliminary first principles: definitions, premises, units, invariants, unknowns and potential falsifiers. Existing observations may seed the frame. Mark unknown premises rather than inventing facts, and append revisions when observations contradict the model.
2. Preregister competing explanations, predictions, boundary conditions and the smallest discriminating experiment. Preserve uncertainty, dissent and a result that would change the plan.
3. Ingest bounded sources with exact provenance, then record observations separately from reports, assumptions and simulations. Use explicit `not_applicable` with a reason where numeric units or uncertainty do not apply.
4. Separate deduction from declared premises, induction over a declared sample/domain, abduction among explanations, and analogy as a search aid. Finite examples do not prove a universal law.
5. Reframe a blocked operation into smaller subproblems. An exact analogy needs an explicit relation/operator/invariant mapping and appropriate proof or test scope. An approximate analogy needs a metric/error limit or an explicit unknown, domain limits and lost invariants. Translate the result back and rerun original acceptance tests.
6. Use bounded combinatorial Ideonomy for a named gap, blockage or design trade-off: typed primitives, explicit pair compatibility, resource bounds, diverse candidates, rejection reasons and a legitimate no-useful-candidate outcome. A lacuna is a concrete missing observation, mechanism, connection or obligation. Alien-science/alternative-axiom/notation candidates are speculative operational models with human baselines and falsifiable predictions; a new glyph does not establish novelty, alien origin, physical reality or a theorem.
7. Run skeptical checks for confirmation, selection, measurement and publication bias; confounding/base rates; anchoring and correlated reviewers; circular reasoning, authority/consensus fallacies and category errors between simulation, compilation, proof and physical validation. Preserve negative/null outcomes and counterexamples.
8. Append the plan update with exact observations, artifacts, parent version, failed hypotheses, next information-gaining experiment and defect prevention. Independent CACE verification and canonical promotion stay separate.

Two coding agents are collaborating in this session. Persistent runtime coder/evaluator adapters are a separate incomplete integration; fixture tests do not establish a live self-improving dot.

## Representation lenses considered by default

| Lens | Required meaning and gate |
|---|---|
| Simplex | State dimension and affine/convex assumptions; validate weights and invariant mappings. Normalized weights are not proof and have no automatic probabilistic interpretation. |
| n-ality | State arity, typed relationships, composition and dimensional constraints. An n-ary shape does not establish physical synergy. |
| Continuum | State domain, operators, boundary/initial conditions and approximation scope. Numerical continuum claims need discretization-error, convergence and stability checks. |
| Fuzzy logic | Define membership, aggregation and thresholds. Membership is not probability; authorization and verification remain Boolean. |

Record `applicable`, `irrelevant` or `deferred`, with a reason, for each lens. Do not force an irrelevant representation. A chosen transformation must preserve declared invariants within its error/domain scope and pass the original task's acceptance tests. The parent's typed helpers and protocol integration need exact evidence before any deployed-capability claim.

## Just-in-time repair and bug-sweep architecture

Routine authorized reversible repairs should proceed with a bounded impact assessment and targeted verification. Resolve authorization from the active user session and repository policy; do not invent a blanket manual-approval gate for ordinary fixes. A repair does not silently widen the shared-runner tool allowlist, signer access or execution authority.

Make repairs inexpensive to investigate: typed stage boundaries, invariant assertions, structured failure classes, dependency-derived source/test impact, correlated artifact/task/stage IDs, small reproducers, fault injection, sibling-pattern sweeps, preventive regressions and scoped rollback. Derive the index from canonical source/contracts/tests/receipts, rather than maintaining another truth database.

Three concrete deployment families seed that work:

| Family | What was observed | Prevention and remaining evidence |
|---|---|---|
| Import shadowing | Source review found privileged seeding used `-s` and inherited runner import paths; no exploitation was observed | `-I -B`, explicit verified package path and trusted cwd; the isolated-child regression exercises malicious cwd, `PYTHONPATH` and `PYTHONHOME`. Sweep sibling bootstrap/client/service paths. |
| Restrictive umask | Source review and a restrictive-umask fixture showed implicit modes could block the service UID; this was not a live-outage claim | Explicit source/release/config modes and state ownership; preserve umask-077 regression and inspect socket traversal permissions. |
| Actions metadata permission | Parent reports a first attempt failed with 403 before host mutation, followed by successful deployment | Operation-specific minimal permissions and fail-before-mutation checks; link the first failure's exact run/log before declaring the family fully closed. |

Keep failed attempts, skipped gates and `NOT_RUN` visible. Reconcile an ambiguous external call by its idempotency key before retry. Recovery must preserve prior evidence and verify that rollback restores the original invariant; do not delete unrelated runner data.
