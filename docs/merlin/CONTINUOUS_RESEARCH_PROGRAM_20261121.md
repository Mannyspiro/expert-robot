### The recovered chip foothold

PR63 head `799adbcde7b4a97787584fabd689e3bea5424d7d` contains synthetic
electrothermal sheets and independently assembled P1 references. The full-square
reference already uses `k(x,y)=1+x` and `u=x(1-x)y(1-y)` on grids 5, 9 and 13;
it explicitly reports no actual CACE variable-coefficient execution. Older
documentation proposing this square reference is therefore partly superseded
by its code. Do not invent a duplicate reference and call it new progress.

The historical CACE P1 contract pins
`0e7aa229d3bb57174e281b883ee8af5445f15f75` and requires an actual module chain,
independent nodal comparison and independently reconstructed residuals at most
`1e-7`, plus separately calculated manufactured-solution errors. The finite
network tests require exact charge, electrical-power and thermal balances.
These are recovered acceptance conditions, not newly executed results.
Synthetic material constants, a virtual chip resource budget, a small mesh or
CSR round-trip do not establish calibrated semiconductor physics, a continuum
error certificate, transistor TCAD, a foundry PDK or fabrication qualification.

## One bounded cycle

1. Resume the latest completed or partial checkpoint, refresh live repository
   heads and check the actual installed capabilities. Historical PRs and source
   files are recovery inputs, not proof of deployment.
2. State the question, baseline, assumptions, competing hypotheses, observables,
   falsifier, source coverage and unknowns. Use the typed research protocol where
   installed and authorized. Assess simplex, n-ality, continuum and fuzzy logic
   with an applicability decision, invariant/test and limitations.
3. Acquire bounded public sources. Use the accepted Merlin browser route when
   native deployment and the connected request path are verified. Preserve exact
   URLs, response/status/redirect data, rendered observations and action traces.
   If that route is unavailable, continue independent read-only research and
   identify the exact missing step. ChatGPT account/UI access is excluded.
4. Select at most one reversible implementation candidate. Freeze reference and
   fresh held-out checks before testing. Use distinct coder/reviewer roles when
   available, and state when independent evaluation is missing.
5. Run only admitted work, preserve failed hypotheses and costs, and compare
   the result against the original acceptance conditions. Keep the baseline
   when no candidate passes.
6. Append raw evidence, exact identities, the decision and the next checkpoint.
   Notify for a tested improvement, meaningful negative result, concrete blocker
   or necessary specification request; avoid repetitive empty updates.

At most **three browser episodes** and **one operation at a time** are admitted
per cycle, under the installed limits and resource headroom. The initial branch
tick budget is one. Typed Ideonomy defaults to 256 examined combinations and
16 results, with a zero monetary cost ceiling and explicit omitted scope.
The program does not itself enforce a host process deadline: the recurring task
must honor the actual cycle deadline and the independently enforced component
limits. No budget is increased by this record.

External model spend remains **$0**. Do not silently replenish an exhausted
experiment or replay an ambiguous provider invocation. Existing approval,
independent verification and qualification boundaries remain in force.
Unattended merges, releases and live deployment remain with the operator.

## Source and evidence discipline

News may identify leads; use primary technical sources and exact versions for
technical claims. Relevant upstream watches include GEPA, memory/retrieval
methods, libraries Merlin actually uses, official advisories, public scientific
software, NASA's software catalog and relevant Technology Transfer listings.
The research plan adds no source-domain allowlist. Site access controls,
anonymous browser isolation and installed network/resource policy still apply.

Ideonomy starts from a concrete blockage, unexplained observation, design
trade-off or search gap. Require explicit compatibility, testability and a
bounded cost. A useful analogy needs an invariant, counterexample and a test
after translating back to the original task. A missing ledger entry is not
proof of global novelty.

Keep source captures, conjectures, simulations, numerical measurements, compiled
formal statements, independent verification, held-out capability results and
physical measurements separate. A Lean proof establishes its formal statement
under its stated assumptions; a three-mesh trend is not a convergence theorem.
Accumulated context, saved browser navigation, a schedule or a passing local
test is not evidence of trained weights or general autonomous improvement.
