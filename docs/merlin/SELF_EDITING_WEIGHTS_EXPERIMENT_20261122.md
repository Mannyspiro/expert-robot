# Merlin self-editing weights experiment — 2026-11-22

**Research and candidate only. No Qwen GGUF weights were changed, trained or deployed.**

## Sources and differences

- [Language Models Can Rewrite Their Own Weights](https://arxiv.org/abs/2611.21885), Jiajun Fan et al., submitted November 16, 2026; v2 November 18. Their 27B language model edited its own weights without gradients and gained 6.6 points on 490 held-out problems. The smaller 2B/4B/9B family members did not reliably improve. Merlin's current Qwen 1.5B GGUF does **not** inherit the reported 27B ability.
- [Self-Adapting Language Models — SEAL](https://arxiv.org/abs/2506.10943), Adam Zweiger et al., 2025; [research implementation](https://github.com/Continual-Intelligence/SEAL). A model generates training examples and finetuning directives, and gradient optimization makes lasting updates.
- [Hugging Face PEFT quantization guide](https://huggingface.co/docs/peft/developer_guides/quantization), [Qwen2.5-Coder-1.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-Coder-1.5B-Instruct). A supported HF/safetensors training checkpoint and GPU are required for QLoRA. A q4_k_m GGUF inference file is not a drop-in gradient-training checkpoint.

## Implemented (review branch only)

1. python/merlin/self_rewrite_lab.py: real numeric edit of a tiny synthetic 2x2 matrix via bounded gradient-free rank-one projection. Independently checks a frozen held-out set, rejects regressions, and preserves the original. The direction is algorithmic, **not generated by an LLM**.
2. python/merlin/tiny_torch_lora_proof.py: real CPU PyTorch LoRA gradient updates on a tiny frozen neural network. Local measured 0/4 to 4/4 on a simple synthetic held-out linear task; no Merlin Qwen weights changed.
3. python/merlin/self_edit_data_proposer.py: typed self-generated arithmetic training data; independently recomputes every answer, rejects duplicates, malformed model output, untrusted code and heldout question overlap.
4. python/merlin/qwen_lora_candidate.py: resource-gated, explicit opt-in Qwen2.5-Coder-1.5B local checkpoint 4-bit QLoRA. Restricts trainable modules, rank/steps and GPU headroom. Evaluates on untouched heldout questions and writes a separate adapter candidate only if accuracy increases without case-level regressions.
5. python/merlin/self_training_loop.py: local-model proposal -> independent arithmetic oracle -> temporary verified training set -> separate QLoRA training -> holdout gate. The language model does not get held-out answer labels, execute tools or alter production. Operator-declared GGUF SHA is **not an independently attested loaded-checkpoint hash**.
6. GitHub Actions merlin-self-weight-edit-lab.yml: synthetic exact-source tests, real tiny numeric rewrite and negative boundary tests. Does **not** execute Qwen GPU training.

## Evidence and limitations

Local CPU PyTorch 2.10.0 demonstration: a rank-one adapter was actually updated with SGD; original tiny base stayed unchanged. Holdout correctness rose from 0/4 to 4/4 and mean absolute error fell from 1.5 to about 1.56e-7. This measures a trivial synthetic linear function, not model language capability or recursive improvement. The repo script can reproduce this result with PyTorch installed.

GitHub Actions has passed the synthetic model-edit, data-validation, Qwen dry-run and self-training composition contracts. The live packaged ARM64 Qwen GGUF inference remains separate and unchanged. No supported CUDA training device, locally provisioned full Qwen safetensors checkpoint or exact training dependency manifest was established for full-model adaptation, so it was not run.

## Runnable gated Qwen path

Preflight (no training):
- PYTHONPATH=python python -m merlin.qwen_lora_candidate --model-dir /private/qwen-trainable --train-json /private/train.json --heldout-json /private/heldout.json --output-parent /private/candidates

Explicit training adds --execute --steps 12 --rank 4, only after local Qwen model / tokenizer / safetensors and compatible pinned torch, transformers, peft, accelerate, bitsandbytes are independently verified. GPU admission requires at least 8 GiB free as a minimum (not a promise against out-of-memory errors).

For SEAL-like data proposal, start a known local inference server, then run python -m merlin.self_training_loop with the required endpoint, GGUF digest, trainable checkpoint directory, heldout JSON and candidate directory, plus --execute. No downloaded model, raw chat or model output should be published in CI.

## Release gate and next scientific test

A candidate stays unpromoted until an independent evaluator tests a larger domain-balanced untouched holdout, regressions and safety/tool use, replicates with another seed, checks peak GPU/host RAM/latency/cost, confirms loaded weight identity and validates rollback and license. No score from tiny data can prove generalized gain. Paper-style **direct LLM-driven rewriting of its own weight tensors** remains experimental for a 1.5B model; the implemented self-proposal currently generates bounded training data, while the direct tensor edit proof is synthetic.

Mathematical lenses: simplex deferred (no barycentric mixture); n-ality applied to independent checkpoint/dataset/score/resource/authority axes; continuum applied to bounded learning rates and perturbations; fuzzy preference membership not permitted to soften binary validation or authorization.

**Decision:** leave Merlin's working GGUF immutable; prepare trainable full-checkpoint LoRA candidate only on admitted local hardware. Preserve negative and null findings and require evidence before any upgrade.
