## Root-cause and sibling repairs

- First fully isolated connected-browser assembly [#45015906990](https://github.com/morganaspim/Cace-app/actions/runs/45015906990) failed before staging due to an undefined first-stage helper; corrected without changing source acceptance.
- The next isolated run [#45015957524](https://github.com/morganaspim/Cace-app/actions/runs/45015957524) passed 112/112 and failed in browser-only work at network-interface activation (`EPERM`). Independent read-only namespace test [#45016245288](https://github.com/morganaspim/Cace-app/actions/runs/45016245288) observed `ENETUNREACH` errno 101 for AF_INET loopback without interface administration. Neither run may be promoted as fully isolated browser acceptance.
- The first limited host-loopback attempt [#45016386594](https://github.com/morganaspim/Cace-app/actions/runs/45016386594) also passed 112/112 but exposed a separate controller bootstrap failure: Python `-I` excludes the script directory, so direct `server.py` invocation could not import `engine`. Fixed both strict and limited sibling browser controllers by binding the pinned Studio package directory explicitly in an isolated `-c` bootstrap rather than dropping `-I`. The exact source SHA/binary pins were updated before the successful rerun [#45016586418](https://github.com/morganaspim/Cace-app/actions/runs/45016586418).
- Earlier [#45015468598](https://github.com/morganaspim/Cace-app/actions/runs/45015468598) separately proved the original UI's JavaScript and screenshot under **true offline network namespace**, but without server. It correctly displayed a disconnected banner. The two acceptance scopes are deliberately distinct.
