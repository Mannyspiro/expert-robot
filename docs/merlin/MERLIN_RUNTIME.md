# Merlin runtime and research handoff

For a request to use Merlin, resolve the exact completed Xenomaths x86-64
USB build from [usb/release.json](usb/release.json). Check the artifact
with [the USB verifier](usb/README.md) before booting it on an authorized
host or using its extracted application. Report whether the run used a
booted guest, the ISO payload running on a host, or an approved remote
instance with its image identity independently verified. If there is no
runtime or image access, record that blocker and accurately identify any
fallback work.

## Skeptical scientist workflow

Use the user's Merlin skeptical scientist skill where available. The
following project instructions also apply when a chat has repository
access alone.

1. Recover the project revision and exact evidence. Identify runtime,
   input, model, proof, scene, and output versions.
2. State the question, baseline, observable, units, assumptions,
   alternatives, falsifier, and stopping rule before comparing results.
3. Evaluate simplex, n-ality, continuum, and fuzzy representations for
   the actual problem. Mark each applied, deferred, or inapplicable with
   the applicable invariant or limitation. Use bounded Ideonomy when
   enumerating options. Track tested, rejected, and untested options.
4. Preserve raw outputs and failed runs. Challenge conclusions with
   negative controls, independent checks, and relevant boundary cases.
5. Label claims as design, simulation, physical measurement, or formal
   result. Cite the underlying source. Log what changed and the next test.
   Keep tool and release promotion under the repository's review process.

GitHub-connected chats can read these instructions when they open this
repository or choose the pull request branch. The GitHub release record
identifies the image. ISO bytes and recovery access remain subject to the
delivery routes described in the USB handoff.

For film, use the [Merlin production workflow](studio/README.md).
