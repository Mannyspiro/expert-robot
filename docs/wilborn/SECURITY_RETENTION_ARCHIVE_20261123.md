## Retention implementation
Host specifies a positive reserve below the fixed cap; the advisory reports remaining revisions and review due, not a retention or deletion authorization. The archive reuses the existing exact-anchored backup and bounded encrypted copy helpers. It contains encrypted history and canonical signed anchor/review receipts; the review binds encrypted database bytes, state identity, revision and receipt hash. No raw incident payloads or private keys. Stage under a new private directory and require a separate reviewer, fresh retained tip, no overwrite. Inspect a temporary copy using the historically signed time, never return a live ledger or bypass current anchor freshness. Archived receipt validity under pinned trust does not establish independent real-world time, later revocation status or permission to restore. Current custody remains the live rollback boundary. No automatic deletion, rotation, production archive retention period, or activation; operator must quiesce writers, retain old keys and independent trust, and review a successor before reaching capacity. Actual independent key custody and OCI/private-host qualification remain open.

N-ality: revision count, age, storage, signature identity, history completeness, current recovery authority and archive retention are independent axes. Fuzzy/simplex/continuum cannot soften exact cap or integrity checks; no extrapolation to arbitrary workloads. Alternative: independently anchored rotated segments reduce active history length but require a reviewed cross-segment continuity/activation contract; not introduced by this archive.
