## Experiment
Baseline: in-memory synthetic monitor. Hypothesis: authenticated ordered events, a single encrypted SQLite checkpoint and atomic transactions preserve deduplication and pending alerts across restarts. Use the existing CACE verifier, Titan HKDF/AES-GCM-SIV implementation, ArtifactRef value type and correlation rules. Reuse the shared rule transition code. Do not store plaintext telemetry in the research registry. The local operational checkpoint is not a competing canonical research ledger.

Acceptance: exact signed event fields, separate pinned sensor/operator roles, monotonic sequence, idempotent current retry, older sequence/gap/conflict rejection, stale and untrusted signature rejection; multiple writers serialize; restart retains counts and active windows; signed review is bound to exact current checkpoint, changes no authorization, and never clears evidence counts. Wrong keys, mutated ciphertext, absent checkpoint, changed trust and supplied external minimum revision reject. Report is static HTML generated only by trusted local host code, with no network requests or scripts. No raw prompts, credentials, client records or sensor/operator names in report. Bounds: one ordered sensor stream per ledger, one encrypted row, bounded windows and counters, no raw log history. Synthetic test keys only.

## Limitations and next gates
This is an experimental local checkpoint, not a production evidence journal. Provision it in a host-private directory, with protected storage and independently managed keys. Explicit creation only; failed creation needs operator repair. No automatic key rotation or migration, authenticated live sensor, alert delivery, durable incident history, production retention policy, cross-host correlation, hardware key custody, qualified OCI deployment or live ChatGPT connector. Encryption cannot prevent deletion or whole-file rollback; a trusted externally maintained minimum revision is needed for rollback checks. A fresh signed retry is required; old events cannot be accepted after expiry. One pinned sensor stream must use stable sequences and preserve its own retry state. Signed statements do not prove sensor truth. Acknowledgement is not remediation or proof of compromise. The existing HTTP/LLM monitor remains separate; its trusted events need a future signed local sensor bridge. No actual upstream ARTEX executable is used.

n-ality: distinct identity, scope, sequence, clock, signature, revision, authorization and review axes. Exact categorical gates, not simplex/continuum/fuzzy scores. Possible correlated false positives, key compromise, time anomalies and whole-file rollback are not cured by a passing test suite. Use independent controls, fixture negative cases and fresh-process replay; preserve failures. OCI is unnecessary for the portable synthetic CI slice, but remains a later host-specific qualification gate.
