# Signed local security producers and encrypted history
Parent ecf8ffe2fb4df20ab0455dac1275de1acccbd12c. All three CI workflows passed, including 94 business/security tests, 8 CACE tests and the separate-process recovery test. Native run 45305371967; prototype 45305372029; public replay 45305371956.

## Scope and experiment
Reuse the typed event producers, existing ledger, CACE verifier, Titan envelope and correlation code. A trusted local sensor callback allocates a sequence and signs under the same SQLite transaction, never transmits raw payloads. A bounded encrypted revision history preserves event and acknowledgement transitions, with parent digest continuity. An independently pinned signer may attest an externally held checkpoint revision/hash; the host supplies it, and verification rejects rollback behind it or a divergent history. No signing keys are generated by runtime code. No live external anchor store, production signer custody or cross-host telemetry is claimed. Existing v1 ledger files require an explicitly reviewed migration; no auto-reset. Cap is 1024 revisions, fail closed rather than delete history. Full chain verification costs O(revisions) per read/write; performance and retention require later qualification. No protection against compromise of all host keys or stale anchor supplied by the host. A signed anchor checks its exact revision; later unanchored writes remain a rollback exposure.

Acceptance: existing regression suite; HTTP and LLM producers plus passive ARTEX fixtures use same signed adapter; concurrent local sequence allocation; signer rejection leaves no new revision; encrypted history survives acknowledgement; deletion or mutation rejected; exact separately signed anchor rejects a restored older copy; static dashboard shows incident history and anchor status, contains no raw secrets; complete triage coverage. Test all using fixture keys and synthetic data. Dashboard is a local read-only view ready for a Studio host adapter; packaged Studio source is a separate ZIP and is not modified here. Do not equate this with installed Studio or OCI production integration.

N-ality: identity, event type, order, encryption, anchor, and review remain independent. Fuzzy/simplex/continuum not applicable to exact authorization. Alternatives: local encrypted append history alone cannot detect whole-file rollback; independent anchor is necessary but does not prove source truth. Correlated benign events may trigger review; no automatic remediation. The OCI typed job gateway has no approved profile for this service. Preserve existing authority, no new self-hosted arbitrary-code lane.
