# Merlin UiPath implementation map

This directory contains the cross-platform UiPath implementation contract. It separates workflow intent from Studio-generated project metadata.

## Supported execution surfaces

| Surface | Role | Boundary |
|---|---|---|
| UiPath Studio Desktop on Windows | Build, debug and run Windows desktop workflows; UI automation; local process execution; archive handling | Not the project registry or research reasoning engine |
| UiPath Studio Web in a browser, including macOS | Build/run supported cloud and API-first workflows where account entitlements and activities support them | Not Windows desktop UI automation; do not assume Desktop XAML projects run unchanged |
| Merlin / Expert Robot | Task authority, project registry, worker routing, provenance and evidence aggregation | No unbounded arbitrary command execution |
| GitHub | Canonical source history and review | No automatic approval of consequential changes |
| Avrea | Bounded CI/compute execution | Not authority or a substitute for verification |
| CACE / Lean | Independent formal qualification | A successful build does not validate assumptions or physical interpretation |
| Hermes | Typed routing among registered workers | No permission escalation |

## First implementation slice

1. Keep project.json and XAML generated by the installed Studio version. Do not hand-author a guessed Studio project manifest.
2. Use Data/task.schema.json and Data/evidence-receipt.schema.json as versioned cross-platform contracts.
3. Implement a small dispatcher with explicit states: Idle -> Load -> Validate -> Plan -> AwaitApproval -> Execute -> Verify -> Receipt -> Complete.
4. Start with local attended Windows execution for archive intake and read-only GitHub inspection.
5. Implement Studio Web workflows separately around supported HTTP/API activities and the same JSON contracts. Share contracts and service endpoints, not assumptions about UI automation or XAML portability.
6. Record Studio version, activity package versions, runtime, workflow commit, task ID and source commit in every receipt.

## Repository/account routing

- Mannyspiro/expert-robot uses the Primary GitHub connection.
- morganaspim/Cace-app uses the separate MorgansCace connection.
- Resolve owner/repository from an exact registry record. Never infer the owner from a display name.
- Read-only is the default. Writes are limited to explicitly approved feature branches and draft PRs.

## Safety invariants

- Capability grows; authority never expands.
- Never execute archive contents during intake.
- Never accept arbitrary shell commands or executable paths from task input.
- Never place credentials in source, XAML, task payloads, logs or evidence receipts.
- Never merge, deploy, change permissions or alter credentials automatically.
- A source SHA change invalidates dependent verification receipts.
- A timeout or failed verification moves the task to a visible failure/quarantine state; no infinite retries.

## Studio setup gate

The repository does not claim UiPath is installed or activated on the user's Windows device. Before committing generated Studio files, record the actual Studio version and create the Windows project in Studio. Studio Web work can proceed against shared contracts without pretending it is a Windows desktop robot.
